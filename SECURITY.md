# Security Policy

Provus is trust infrastructure. Security is not a feature — it is the product.
This document covers the threat model summary, known limitations, and how to
report vulnerabilities.

## Threat model summary

The full threat model is documented in the Technical Specification Document
(TSD Section 8, `docs/architecture/`). This is a summary for security researchers.

### Protected assets

| Asset | Description |
|-------|-------------|
| Identity record | Cryptographic binding between agent and key pair |
| Attestation record | Signed endorsement from credentialed attester |
| Reputation signal | Aggregate of task records, deviation events, peer assessments |
| Attester graph | Tier 0–3 hierarchy and credentialing relationships |
| Query integrity | Trust query returns accurate, current answer |

### Key threat vectors and mitigations

**T1 — Key compromise at provisioning (Critical)**
Mitigation: Enclave-mode provisioning (hardware), key rotation with lineage link.
Residual: compromise-to-detection window.

**T2 — Fabricated attestation (Critical)**
Mitigation: Ed25519 signature verification at Relay before Anchor write.
Residual: colluding Relay operator or stolen attester key.

**T3 — Reputation pollution via false incident records (High)**
Mitigation: Attributable filings, signed rebuttal append model.
Residual: damage window before rebuttal propagates.

**T4 — Attester key compromise (Critical — highest single-point impact)**
Mitigation: Key rotation, demotion propagation, HSM requirement for Tier 1.
Residual: compromise-to-detection window. HSM use strongly recommended.

**T5 — Colluding agent ring (Medium)**
Mitigation: Graph-structural anti-collusion scoring, floor rule on peer-only attestations.
Residual: sophisticated low-density rings are harder to detect.

**T6 — Sybil attack on mesh (Medium)**
Mitigation: Tier 2 admission cost (90-day tenure, Tier 1 touch point, clean incident record).
Residual: patient adversary paying admission cost at scale.

**T7 — Relay node compromise (High)**
Mitigation: Freshness TTL, authoritative query path, high-severity revocation fast path.
Residual: active selective suppression without stale-data detection.

**T8 — Anchor quorum attack (Existential)**
Mitigation: Multi-institution diversity, MonadBFT consensus (production).
Residual: requires simultaneous multi-institution compromise.

**T9 — Protocol-level denial of service (Medium)**
Mitigation: Tier admission cost, Relay rate limiting.
Residual: multi-identity load at scale.

### Explicit out-of-scope threats

The following are outside the technical threat model by design — not oversight:

- **Insider threats at Tier 0** — governance and due diligence problem, not a protocol problem
- **Behavioral safety of attested agents** — Provus attests evaluation was performed; not that the agent is safe
- **Zero-day cryptographic breaks** — Ed25519 / SHA-256 assumption; not specific to Provus
- **Social engineering of human operators** — outside the technical boundary
- **Conflicting attestations from competing Tier 1 attesters** — governance problem; protocol records both

## Known limitations

### Revocation lag
There is a window between when a compromise is known and when it is universally
reflected in query results. High-severity revocations use a dedicated push path
targeting <5 seconds full propagation. Standard revocations follow the normal
propagation cycle (<30 seconds). Relying parties operating in high-risk contexts
**must** set short cache TTLs.

### PoC consensus model
The current Anchor node uses a threshold majority consensus model for the PoC.
Production deployment requires MonadBFT (arXiv:2502.20692) for Byzantine fault
tolerance. The production consensus hook is in place (`anchor/consensus.ts`) but
MonadBFT integration is not yet live.

### Key management
The SDK does not prescribe key storage. Private keys generated by the SDK are
held in memory and returned to the caller for secure storage. In production
deployments, private keys **must** be stored in an HSM or secure enclave.
The SDK explicitly documents this non-guarantee (TSD §7.4).

### Peer-only trust networks
Agents with no Tier 0–2 attestation anchoring receive a floor-level trust score
of 0.1 regardless of peer attestation volume. This is enforced in
`packages/core/src/enforcement.ts`. Operators relying solely on Tier 3 peer
attestations for high-stakes authorization decisions are operating outside the
intended security model.

## Responsible disclosure

Provus is pre-production infrastructure. We take security reports seriously and
will respond to all credible reports.

**To report a vulnerability:**

1. **Do not open a public GitHub issue.** Public disclosure before a fix is
   available endangers the protocol and its users.

2. Email `hello@devajibola.me` with subject line:
   `[PROVUS SECURITY] Brief description`

3. Include:
   - A description of the vulnerability
   - The affected component (`packages/core`, `packages/sdk`, `packages/node`)
   - Steps to reproduce
   - Your assessment of severity and exploitability
   - Any suggested mitigations

4. We will acknowledge within 48 hours and provide a remediation timeline
   within 7 days.

**Scope:**
- `packages/core` — cryptographic primitives, protocol operations, enforcement
- `packages/sdk` — HTTP surfaces, state management, routing
- `packages/node` — Edge, Relay, and Anchor node implementations

**Out of scope:**
- Social engineering attacks
- Attacks requiring physical access to infrastructure
- Vulnerabilities in third-party dependencies (report upstream)
